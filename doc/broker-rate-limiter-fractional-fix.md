# Исправление дробной пропускной способности брокера

## Причина

Прежний `BrokerRateLimiter` ограничивал накопление токенов величиной
`max(1, capacityRps × tickSeconds)`. При поступлении пакетов каждый тик
дробный остаток предыдущего тика обрезался перед обработкой следующей партии.
Например, профиль Mosquitto на 36087,894937787474 RPS при tick 0,1 мс
давал примерно 30000 RPS вместо заданной пропускной способности.

В сохранённой калибровочной симуляции `m16.q0.p1.s42` это привело к
60880 отказам лимитера из 360889 попыток (16,869%). Такие отказы нельзя
приписывать реальному брокеру: в соответствующей натурной точке publish failure
равен нулю.

## Изменение

Ёмкость token bucket теперь равна бюджету одного тика плюс одному токену.
Дополнительное место сохраняет дробный остаток, меньший одного сообщения,
при поступлении следующего бюджета. Начальный баланс остаётся нулевым;
после простоя накопление ограничено этой ёмкостью, а не всем временем простоя.
Для целочисленных скоростей максимально допустимый всплеск увеличивается
на одно сообщение; установившаяся скорость не увеличивается.

Допуск сравнения на границе целого токена составляет 1e-9 токена:
прежние 1e-12 давали ложный отказ после 100000 дробных пополнений
при 3333,3 RPS. Перегрузка по-прежнему вызывает отказы.

## Проверки

Новые проверки на прежнем коде воспроизвели дефект: 7 из 8 проверок
дробных скоростей завершились ошибкой.

После исправления проверяются:

- скорости ниже, около и выше частоты тиков, включая реальное значение Mosquitto;
- установившийся приём при перегрузке с погрешностью не более одного сообщения;
- отсутствие отказов у партий, полученных округлением заданного cumulative offered load;
- ограничение всплеска после длительного простоя и бюджета на каждом следующем тике;
- сброс накопленного кредита при `Update`;
- полный BrokerFidelity для QoS 0/1/2: нулевые искусственные отказы,
  завершение всех попыток, доставка и точное повторение summary.

Результат выбранного набора после исправления: **76 passed, 0 failed**.
Сборка CLI также завершилась успешно.

Проверки полного пути используют warmup 100, measurement 1000, drain 1000
тиков при tick 0,1 мс. Это регрессионные тесты, не замена кампании.
Дополнительный более длинный диагностический запуск с measurement 10000
тиков прошёл QoS 0/1; его QoS 2 был прерван после затянувшегося исполнения
и не считается успешной проверкой длительной нагрузки.

Команда выбранного набора:

```powershell

```

## Граница применимости

Это изменение модели, которое меняет научные результаты. Старые симуляции
нельзя перезаписывать или объединять с исправленными без обозначения ревизии.
Натурные observations и замороженные профили можно использовать повторно;
исправленные симуляции требуют отдельного каталога, provenance и повторной
проверки fidelity. Исправление лимитера само по себе не подтверждает точность
p99, потерь доставки или MqttRelay и не решает ограничения памяти/скорости.
